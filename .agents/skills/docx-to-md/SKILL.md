# docx → agent-friendly Markdown (с картинками)

Готовит `.docx` к чтению AI-агентом: чистый Markdown с текстом и таблицами **плюс
картинки отдельными файлами**, на которые в MD стоят рабочие ссылки
`![](media/<имя-исходника>/imageN.png)`. Картинки каждого документа лежат в своей
подпапке `media/<имя-исходника>/`, поэтому конвертация нескольких `.docx` в одну
папку не перезаписывает чужие картинки.

## Зачем (обоснование)

Бенчмарк форматов показал: по тексту и таблицам форматы (MD/PDF/DOCX) равны, а
водораздел — **визуал** (макеты, скриншоты, значения на картинках, цвета). При этом:

- **`markitdown` в одиночку не подходит**: по умолчанию вырезает картинки в битые
  плейсхолдеры `![](data:image/png;base64...)` (визуал теряется); с `--keep-data-uris`
  инлайнит гигантский base64 — MD раздувается в разы, а агент читает `.md` как
  **текст** и base64 в изображение не декодирует (визуал всё равно недоступен).
- **PDF нативно** даёт визуал, но дорого (страницы как изображения, ~×2 токенов).

Оптимум — **дешёвый MD + картинки файлами**: агент читает текст почти даром, а
нужный макет открывает через Read **по требованию**, получая настоящее изображение.

## Когда использовать / не использовать

- **Использовать**: на входе `.docx`, в котором есть картинки/макеты, важные для
  задачи, и документ отдаётся агенту на чтение/анализ.
- **Не использовать**: источник — PDF (в нём растр страниц, отдельных ассетов нет —
  тут лучше нативный Read PDF) или уже сломанный MD-экспорт (картинки уже потеряны,
  доставать нечего). Картинки живут только внутри `.docx`.

## Требования

- Python 3.8+
- `markitdown` в PATH: `pip install "markitdown[docx]"` (проверьте `which markitdown`)
- Опционально `defusedxml` (XXE-safe парсинг): `pip install defusedxml`

## Использование

```bash
python3 scripts/convert.py <input.docx> [output_dir]
```

**Папку результата задаёт пользователь** — передавай тот путь, который он назвал.
Если пользователь папку не указал, `output_dir` можно опустить: по умолчанию
результат кладётся **в ту же папку, где лежит исходный `.docx`**.

```bash
# по умолчанию — рядом с исходником:
python3 scripts/convert.py "docs/ЧТЗ Каталог.docx"
#   → docs/ЧТЗ Каталог.md  +  docs/media/ЧТЗ-Каталог/

# явно указанная пользователем папка:
python3 scripts/convert.py "docs/ЧТЗ Каталог.docx" build/chtz/
#   → build/chtz/ЧТЗ Каталог.md  +  build/chtz/media/ЧТЗ-Каталог/
```

На выходе:

- `<имя-исходника>.md` — текст+таблицы, картинки как `![](media/<имя-исходника>/imageN.png)` (лёгкий, ~как текст);
- `media/<имя-исходника>/` — все PNG из документа отдельными файлами (подпапка по имени исходника, чтобы не перезаписывать картинки других документов в той же папке).

## Как работает

1. `markitdown` извлекает текст и таблицы (плейсхолдеры картинок идут по порядку).
2. Из `.docx` (это zip) достаются `word/media/*.png`, а порядок картинок берётся из
   последовательности `r:embed` в `word/document.xml`.
3. Каждый i-й плейсхолдер заменяется на ссылку на i-й реальный файл.

Скрипт печатает диагностику соответствия (плейсхолдеры ↔ `r:embed` ↔ файлы). Если
числа расходятся — предупреждает: маппинг по порядку может быть неточным, тогда
**сверьте ссылки визуально** — откройте пару `media/*.png` и проверьте, что картинка
соответствует подписи в тексте рядом.

## После конвертации (как читать агенту)

- Читай `doc.md` штатным Read — это дёшево (текст+таблицы).
- Когда для конкретного места нужен визуал (макет, цвет, значение на скриншоте) —
  открой соответствующий `media/<имя-исходника>/imageN.png` через Read: он придёт как изображение.
