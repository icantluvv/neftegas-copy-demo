# dtoir-nav-sections

## Why

По референсному макету (скриншот) и Регламенту-СОВОФ-ХХХХХ-2026 (планирование
и организация ДТОиР) в сайдбаре ожидаются 4 раздела: «План на 2027»,
«Выполнение», «Корректировка», «Факт». Backend и API-контракт поддерживают
сегодня только домен согласования корректировок (`corrections`) — сущностей
годового плана, мониторинга выполнения и план/факт-отчётности в системе нет
(см. `apps/backend/src` и `api/src/paths`). Полноценная реализация этих трёх
разделов требует отдельных доменов, миграций БД и правок OpenAPI-контракта —
самостоятельных change'ей вне текущего скоупа.

Это изменение — только навигационный каркас: 4 пункта меню, три из которых
(«План на 2027», «Выполнение», «Факт») ведут на страницы-заглушки с честным
статусом «в разработке» и перечнем форм документов Регламента, которые будут
привязаны к разделу в будущих change'ах. Пункт «Корректировка» переиспользует
существующую страницу `/dashboard` без изменения её поведения.

## What Changes

- В `navItems` (`apps/frontend/app/(private)/constants.ts`) добавлены три
  новых пункта — «План на 2027» (`/planning`), «Выполнение» (`/execution`),
  «Факт» (`/fact`); существующий пункт `/dashboard` переименован из «Рабочий
  стол» в «Корректировка» (маршрут и поведение страницы не изменились).
- Добавлен переиспользуемый компонент `SectionPlaceholder`
  (`apps/frontend/src/components/section-placeholder`), рендерящий заголовок,
  описание раздела и список форм документов Регламента со ссылкой на
  соответствующее приложение/пункт (например, «Приложение Б.4»).
- Добавлены три новые страницы App Router: `app/(private)/planning/page.tsx`,
  `app/(private)/execution/page.tsx`, `app/(private)/fact/page.tsx` — каждая
  использует `SectionPlaceholder` со своим набором документов.
- Backend, API-контракт, страница `/dashboard` и её данные не изменяются.

## Capabilities

Навигационный каркас без новой бизнес-логики и без данных с бэкенда —
наблюдаемое поведение ограничено списком пунктов меню и статическим текстом
страниц-заглушек. Delta specs не создаются (`skip_specs: true`).

## Влияние на качество

- Уровень риска: P3
- Затронутые маршруты: `/planning`, `/execution`, `/fact` (новые), `/dashboard`
  (только лейбл в меню)
- Затронутые frontend-компоненты: `SidebarNav`, `navItems`, новый
  `SectionPlaceholder`
- Затронутые backend-модули: нет
- Затронутые API: нет
- TDD-порядок: не применим — статический контент без бизнес-логики
- Обязательные уровни проверки: Static (lint, typecheck), Component-тест на
  `SectionPlaceholder`
- Ручные проверки: переход по всем 4 пунктам меню под ролью FILIAL — каждый
  открывает свою страницу, активный пункт подсвечивается
- План отката: `git revert` коммита правки

## Открытые вопросы (для последующих change'ей)

- **[К]** Критерии статуса объекта в разделе «Выполнение» («Выполняется» /
  «Приостановлено» / «Отменено») не определены Регламентом — требуют решения
  владельца процесса перед реализацией данных.
- Домены `planning`, `execution`, `fact` (объекты плана, МТР, план/факт по
  стоимости и срокам) — предмет отдельных OpenSpec change'ей с правкой
  `api/src/openapi.yaml` и новых backend-сущностей.
