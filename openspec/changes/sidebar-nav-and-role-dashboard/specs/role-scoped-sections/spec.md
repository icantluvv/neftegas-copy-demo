## REMOVED Requirements

### Requirement: Доступ к ролевому разделу только для соответствующей роли
**Reason**: Три отдельных ролевых маршрута (`/filial`, `/cfo`, `/dtoe`) заменяются единой страницей «Рабочий стол» (`/dashboard`), которая на сервере определяет роль текущего пользователя и рендерит только его ролевой дашборд — необходимость в отдельных URL и в защите каждого из них по отдельности отпадает, поведение переносится в требование «Единая страница рабочего стола с рендерингом по роли» этой же capability.
**Migration**: Прямые переходы на `/filial`, `/cfo`, `/dtoe` больше не поддерживаются (маршруты удалены, вернут 404). Пункт меню сайдбара и редирект после входа ведут на `/dashboard` для всех трёх ролей — миграция происходит автоматически для всех точек входа, управляемых системой; внешних ссылок на старые маршруты не предполагается.

## ADDED Requirements

### Requirement: Единая страница рабочего стола с рендерингом по роли

Система SHALL предоставлять единый маршрут `/dashboard`, который на сервере определяет роль текущего пользователя по данным сессии и отображает только дашборд, соответствующий этой роли: `FILIAL` → дашборд филиала, `CFO` → дашборд ЦФО, `DTOE` → дашборд ДТОиР.

#### Scenario: Пользователь с ролью «Филиал» открывает рабочий стол
- **GIVEN** авторизован пользователь с ролью `FILIAL`
- **WHEN** пользователь открывает `/dashboard`
- **THEN** система отображает дашборд филиала

#### Scenario: Пользователь с ролью «ЦФО» открывает рабочий стол
- **GIVEN** авторизован пользователь с ролью `CFO`
- **WHEN** пользователь открывает `/dashboard`
- **THEN** система отображает дашборд ЦФО

#### Scenario: Пользователь с ролью «ДТОиР» открывает рабочий стол
- **GIVEN** авторизован пользователь с ролью `DTOE`
- **WHEN** пользователь открывает `/dashboard`
- **THEN** система отображает дашборд ДТОиР

#### Scenario: Неавторизованный пользователь пытается открыть рабочий стол
- **GIVEN** пользователь не аутентифицирован
- **WHEN** пользователь открывает `/dashboard`
- **THEN** система перенаправляет пользователя на экран входа

#### Scenario: Роль без назначенного дашборда открывает рабочий стол
- **GIVEN** авторизован пользователь с ролью, для которой не определён ролевой дашборд (например, `ADMIN`)
- **WHEN** пользователь открывает `/dashboard`
- **THEN** система отображает экран «Доступ запрещён» вместо содержимого рабочего стола

### Requirement: Ролевой дашборд получает данные только по своей роли

Каждый ролевой дашборд SHALL запрашивать статистику только через эндпоинт, соответствующий его роли, и SHALL отображать экран «Доступ запрещён», если сервер отклоняет запрос как не соответствующий роли пользователя.

#### Scenario: Сервер отклоняет запрос данных дашборда как не соответствующий роли
- **GIVEN** авторизован пользователь, роль которого сервер определяет как несоответствующую запрошенным данным дашборда
- **WHEN** дашборд запрашивает свою ролевую статистику
- **AND** сервер отвечает `403 Forbidden`
- **THEN** система отображает пользователю экран «Доступ запрещён» вместо содержимого дашборда
