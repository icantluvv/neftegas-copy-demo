## Purpose

Даёт проверяющим (ЦФО и ДТОиР) открыть/скачать загруженные филиалом файлы
версий прямо со страницы корректировки, даёт ЦФО кнопку-предохранитель,
откатывающую собственное случайно принятое решение (согласование/возврат)
обратно в состояние «на проверке» без затрагивания истории замечаний, и даёт
Филиалу удалить собственную корректировку, пока она в статусе «Черновик».

## ADDED Requirements

### Requirement: Скачивание файла версии ограничено ролями ЦФО и ДТОиР

Система SHALL разрешать открытие и скачивание файла версии
(`GET /files/{id}/download`) только пользователям с ролью CFO или DTOE,
имеющим доступ к соответствующей корректировке. Система SHALL NOT разрешать
Филиалу — включая владельца корректировки, загрузившего этот файл, — открыть
или скачать файл версии через этот эндпоинт.

#### Scenario: ЦФО с доступом к корректировке скачивает файл

- **GIVEN** корректировка направлена ЦФО, и пользователь авторизован под этим ЦФО
- **WHEN** пользователь запрашивает `GET /files/{id}/download` для версии файла из этой корректировки
- **THEN** система возвращает `200` с содержимым файла

#### Scenario: ДТОиР скачивает файл

- **GIVEN** пользователь авторизован под ролью DTOE
- **WHEN** пользователь запрашивает `GET /files/{id}/download` для версии файла любой корректировки
- **THEN** система возвращает `200` с содержимым файла

#### Scenario: ЦФО без доступа к этой корректировке получает отказ

- **GIVEN** корректировка НЕ направлена ЦФО, под которым авторизован пользователь
- **WHEN** пользователь запрашивает `GET /files/{id}/download` для версии файла этой корректировки
- **THEN** система возвращает `403`

#### Scenario: Филиал-владелец получает отказ

- **GIVEN** пользователь авторизован под ролью FILIAL и является владельцем корректировки, в которую загружен этот файл
- **WHEN** пользователь запрашивает `GET /files/{id}/download` для версии этого файла
- **THEN** система возвращает `403`

### Requirement: Ссылка на открытие/скачивание файла в карточке корректировки

Frontend SHALL отображать в блоке «Комплектность пакета» карточки
корректировки кликабельную ссылку на открытие/скачивание текущей версии
файла — как на названии элемента пакета, так и рядом с номером текущей
версии — только пользователям, для которых `isCfoReviewer` или `isDtoe`
истинно. Frontend SHALL NOT отображать эту ссылку пользователю, для которого
оба признака ложны, даже если у элемента есть текущая версия файла.

#### Scenario: ЦФО видит ссылку на название элемента и на версию

- **GIVEN** пользователь роли CFO с доступом к корректировке открывает её карточку
- **AND** у элемента пакета есть текущая версия файла
- **WHEN** пользователь просматривает блок «Комплектность пакета»
- **THEN** название элемента отображается как кликабельная ссылка на файл
- **AND** рядом с номером текущей версии отображается ссылка «Открыть / скачать»

#### Scenario: Филиал не видит ссылку на файл

- **GIVEN** пользователь роли FILIAL, владелец корректировки, открывает её карточку
- **AND** у элемента пакета есть текущая версия файла
- **WHEN** пользователь просматривает блок «Комплектность пакета»
- **THEN** название элемента отображается как обычный текст без ссылки
- **AND** рядом с номером текущей версии ссылка «Открыть / скачать» отсутствует

### Requirement: ЦФО может отменить собственное решение по корректировке

Система SHALL позволять пользователю роли CFO отменить собственное принятое
решение (`APPROVED` или `RETURNED`) по корректировке через
`POST /corrections/{humanId}/cfo-cancel`, возвращая статус этого ЦФО в
`PENDING` и пересчитывая общий статус корректировки по правилам, уже
применяемым при согласовании. Система SHALL NOT изменять при этом статус или
содержимое ни одного замечания, оставленного этим или другим ЦФО. Система
SHALL NOT разрешать отмену, если статус этого ЦФО по корректировке уже
`PENDING`, или если корректировка уже находится в статусе
`UNDER_DTOE_REVIEW`, `RETURNED_BY_DTOE` или `APPROVED_BY_DTOE`. Система SHALL
NOT разрешать это действие ролям, отличным от CFO, и SHALL NOT разрешать
ЦФО отменять решение по корректировке, к которой у него нет назначенного
статуса.

#### Scenario: Отмена согласования возвращает статус ЦФО в «на проверке»

- **GIVEN** статус этого ЦФО по корректировке — `APPROVED`
- **AND** корректировка ещё не передана в ДТОиР
- **WHEN** пользователь вызывает `POST /corrections/{humanId}/cfo-cancel`
- **THEN** статус этого ЦФО по корректировке становится `PENDING`
- **AND** общий статус корректировки пересчитывается по правилам согласования

#### Scenario: Отмена возврата возвращает статус ЦФО в «на проверке»

- **GIVEN** статус этого ЦФО по корректировке — `RETURNED`
- **AND** корректировка ещё не передана в ДТОиР
- **WHEN** пользователь вызывает `POST /corrections/{humanId}/cfo-cancel`
- **THEN** статус этого ЦФО по корректировке становится `PENDING`
- **AND** общий статус корректировки пересчитывается по правилам согласования

#### Scenario: Отмена не изменяет замечания

- **GIVEN** этот ЦФО оставил замечание, которое было закрыто при согласовании
- **WHEN** пользователь отменяет своё решение `APPROVED` по этой корректировке
- **THEN** статус этого замечания остаётся неизменным

#### Scenario: Отмена недоступна, пока решение ещё не принято

- **GIVEN** статус этого ЦФО по корректировке — `PENDING`
- **WHEN** пользователь вызывает `POST /corrections/{humanId}/cfo-cancel`
- **THEN** система возвращает `400`
- **AND** статус этого ЦФО по корректировке остаётся `PENDING`

#### Scenario: Отмена недоступна после передачи корректировки в ДТОиР

- **GIVEN** статус этого ЦФО по корректировке — `APPROVED`
- **AND** корректировка находится в статусе `UNDER_DTOE_REVIEW`
- **WHEN** пользователь вызывает `POST /corrections/{humanId}/cfo-cancel`
- **THEN** система возвращает `400`
- **AND** статус этого ЦФО по корректировке остаётся `APPROVED`

#### Scenario: Другая роль не может отменить решение ЦФО

- **GIVEN** пользователь авторизован под ролью FILIAL
- **WHEN** пользователь вызывает `POST /corrections/{humanId}/cfo-cancel`
- **THEN** система возвращает `403`

#### Scenario: Кнопка «Отменить решение» видна только когда есть что отменять

- **GIVEN** пользователь роли CFO с уже принятым решением (`APPROVED` или `RETURNED`) по корректировке, ещё не переданной в ДТОиР
- **WHEN** пользователь открывает карточку этой корректировки
- **THEN** в панели действий отображается кнопка «Отменить решение»

#### Scenario: Кнопка «Отменить решение» скрыта, пока решение не принято

- **GIVEN** пользователь роли CFO со статусом `PENDING` по корректировке
- **WHEN** пользователь открывает карточку этой корректировки
- **THEN** кнопка «Отменить решение» не отображается

### Requirement: Филиал может удалить собственную корректировку в статусе «Черновик»

Система SHALL позволять пользователю роли FILIAL, являющемуся владельцем
корректировки, полностью удалить её через `DELETE /corrections/{humanId}`,
только если статус корректировки — `DRAFT`. Удаление SHALL безвозвратно
удалять корректировку вместе со всеми её слотами, версиями файлов (включая
физические файлы), замечаниями, статусами ЦФО и историей. Система SHALL NOT
разрешать это действие для корректировки в любом статусе, отличном от
`DRAFT`. Система SHALL NOT разрешать это действие пользователю, не
являющемуся владельцем корректировки, и SHALL NOT разрешать его ролям,
отличным от FILIAL.

#### Scenario: Владелец удаляет свой черновик

- **GIVEN** пользователь роли FILIAL — владелец корректировки в статусе `DRAFT`
- **WHEN** пользователь вызывает `DELETE /corrections/{humanId}` для этой корректировки
- **THEN** система возвращает `204`
- **AND** повторный запрос `GET /corrections/{humanId}` для этого же `humanId` возвращает `404`

#### Scenario: Удаление недоступно для направленной корректировки

- **GIVEN** корректировка находится в статусе, отличном от `DRAFT`
- **WHEN** владелец вызывает `DELETE /corrections/{humanId}` для этой корректировки
- **THEN** система возвращает `400`
- **AND** корректировка остаётся в системе без изменений

#### Scenario: Филиал не может удалить чужую корректировку

- **GIVEN** корректировка в статусе `DRAFT` принадлежит другому филиалу
- **WHEN** пользователь вызывает `DELETE /corrections/{humanId}` для этой корректировки
- **THEN** система возвращает `403`

#### Scenario: Другая роль не может удалить корректировку

- **GIVEN** пользователь авторизован под ролью, отличной от FILIAL
- **WHEN** пользователь вызывает `DELETE /corrections/{humanId}`
- **THEN** система возвращает `403`

#### Scenario: Крестик удаления виден только у черновика

- **GIVEN** у филиала есть корректировки в статусе «Черновик» и в других статусах
- **WHEN** пользователь открывает таблицу «Мои корректировки»
- **THEN** крестик удаления отображается только в строках со статусом «Черновик»
- **AND** для остальных строк крестик отсутствует
