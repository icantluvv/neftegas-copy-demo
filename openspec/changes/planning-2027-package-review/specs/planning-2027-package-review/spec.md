## ADDED Requirements

### Requirement: Создание плана и состав пакета по типу
Система SHALL позволять только роли Филиал создавать план, выбрав тип плана,
и SHALL формировать состав пакета плана (обязательные и необязательные слоты
документов) по настроенному для этого типа набору требований, включая
главный Excel-слот, присутствующий всегда.

#### Scenario: Создание плана формирует слоты по типу
GIVEN Филиал «Донбассгаз» выбирает тип плана «Пообъектный план ДТОиР»
WHEN Филиал создаёт новый план этого типа
THEN система создаёт план в статусе «Черновик» с новым человекочитаемым ID вида `PLN-000001`
AND план содержит главный Excel-слот и по одному слоту на каждое требование типа плана

#### Scenario: Только Филиал может создать план
GIVEN пользователь роли ЦФО
WHEN он пытается создать план
THEN система отклоняет запрос с ошибкой 403

### Requirement: Направление плана на проверку выбранным ЦФО
Система SHALL разрешать направление плана на проверку только когда все
обязательные слоты пакета содержат хотя бы одну версию файла, и только
центрам финансовой ответственности (ЦФО), связанным с филиалом-автором через
`FilialCFO`.

#### Scenario: Направление блокируется неполным пакетом
GIVEN план в статусе «Черновик», у которого обязательный слот «Пакет документов» не имеет ни одной версии файла
WHEN Филиал пытается направить план на проверку
THEN система отклоняет запрос с ошибкой 400
AND статус плана остаётся «Черновик»

#### Scenario: Направление ЦФО, не связанному с филиалом, отклоняется
GIVEN план филиала «Херсонгаз», полностью укомплектованный
AND ЦФО «АНГНКС» не связан с филиалом «Херсонгаз» через FilialCFO
WHEN Филиал пытается направить план ЦФО «АНГНКС»
THEN система отклоняет запрос с ошибкой 400
AND не создаёт статус проверки для этого ЦФО

#### Scenario: Успешное направление на проверку нескольким ЦФО
GIVEN план филиала «Запорожгаз» полностью укомплектован
AND ЦФО «ОГМ» и «ОГС» связаны с филиалом «Запорожгаз» через FilialCFO
WHEN Филиал направляет план на проверку, выбрав ЦФО «ОГМ» и «ОГС»
THEN статус плана становится «На проверке у ЦФО»
AND для каждого выбранного ЦФО атомарно создаётся независимый статус проверки со значением «Ожидает решения»

### Requirement: Замечания к плану
Система SHALL разрешать оставить замечание к плану только проверяющему, для
которого этот план в данный момент находится на проверке (ЦФО — пока его
статус проверки «Ожидает решения»; ДТОиР — пока план в статусе «На проверке
ДТОиР»).

#### Scenario: ЦФО не может оставить замечание после принятого решения
GIVEN план на проверке у ЦФО «СИУС», статус проверки ЦФО «СИУС» уже «Согласовано»
WHEN пользователь ЦФО «СИУС» пытается оставить замечание к этому плану
THEN система отклоняет запрос с ошибкой 400
AND статус плана не меняется

#### Scenario: ДТОиР не может оставить замечание вне своей проверки
GIVEN план в статусе «Ожидает отправки в ДТОиР» (ещё не направлен в ДТОиР)
WHEN пользователь ДТОиР пытается оставить замечание к этому плану
THEN система отклоняет запрос с ошибкой 400

### Requirement: Возврат плана ЦФО на доработку
Система SHALL переводить план и статус проверки вернувшего ЦФО в состояние
возврата на доработку только когда у этого ЦФО есть хотя бы одно открытое
замечание к плану, и SHALL NOT изменять статус проверки других ЦФО этого
плана при таком возврате.

#### Scenario: Возврат ЦФО переводит план в доработку
GIVEN план на проверке у ЦФО «ПОА» со статусом проверки «Ожидает решения»
AND ЦФО «ПОА» оставил открытое замечание к плану
WHEN пользователь ЦФО «ПОА» возвращает план на доработку
THEN статус плана становится «Возвращён на доработку»
AND статус проверки ЦФО «ПОА» становится «Возвращено»
AND статус проверки ЦФО, ранее согласовавшего план, не изменяется

#### Scenario: Возврат без открытого замечания отклоняется
GIVEN план на проверке у ЦФО «ОГЭ» со статусом проверки «Ожидает решения», без открытых замечаний от этого ЦФО
WHEN пользователь ЦФО «ОГЭ» пытается вернуть план на доработку
THEN система отклоняет запрос с ошибкой 400

### Requirement: Отметка замечания исправленным и удаление замечания
Система SHALL позволять только Филиалу-владельцу плана отмечать полученные
замечания как исправленные, и SHALL разрешать удаление замечания только его
автору и только пока замечание в статусе «Открыто».

#### Scenario: Филиал отмечает замечание исправленным
GIVEN замечание PLR-000201 к плану филиала «Донбассгаз» в статусе «Открыто»
WHEN филиал «Донбассгаз» загружает исправленную версию файла и отмечает замечание PLR-000201 исправленным
THEN статус замечания PLR-000201 становится «Исправлено филиалом»

#### Scenario: Чужой автор не может удалить замечание
GIVEN замечание PLR-000202 оставлено ЦФО «ОГЭ» в статусе «Открыто»
WHEN пользователь ЦФО «ПОЗК» пытается удалить замечание PLR-000202
THEN система отклоняет запрос с ошибкой 403
AND замечание PLR-000202 остаётся в системе

#### Scenario: Автор не может удалить закрытое замечание
GIVEN замечание PLR-000203, оставленное ДТОиР, уже в статусе «Закрыто»
WHEN автор замечания (пользователь ДТОиР) пытается удалить PLR-000203
THEN система отклоняет запрос с ошибкой 400
AND замечание PLR-000203 остаётся неизменным

### Requirement: Повторная отправка после доработки без сброса истории согласовавших ЦФО
Система SHALL разрешать повторное направление плана на проверку ЦФО только
из статуса «Возвращён на доработку», и SHALL NOT сбрасывать статус
согласования ранее одобривших ЦФО при повторном направлении другому ЦФО.

#### Scenario: Статус согласовавшего ранее ЦФО не сбрасывается
GIVEN план, у которого ЦФО «ОГМ» уже согласовал (статус «Согласовано»), а ЦФО «ОГС» вернул с замечанием
WHEN филиал исправляет замечания ЦФО «ОГС» и повторно направляет план только ЦФО «ОГС»
THEN статус проверки ЦФО «ОГС» становится «Ожидает решения»
AND статус проверки ЦФО «ОГМ» остаётся «Согласовано»

#### Scenario: Повторная отправка недоступна вне статуса «Возвращён на доработку»
GIVEN план в статусе «Черновик»
WHEN Филиал пытается вызвать действие «Повторно направить»
THEN система отклоняет запрос с ошибкой 400

### Requirement: Направление плана в ДТОиР
Система SHALL разрешать направление плана на финальную проверку ДТОиР только
когда все обязательные (выбранные при направлении) ЦФО находятся в статусе
«Согласовано», и SHALL предоставлять действие «Направить в ДТОиР» каждому
согласовавшему ЦФО этого плана, а не только последнему принявшему решение.

#### Scenario: Направление в ДТОиР недоступно до согласования всех ЦФО
GIVEN план направлен ЦФО «ОГМ» и «ОГС», ЦФО «ОГМ» согласовал, ЦФО «ОГС» ещё не принял решение
WHEN ЦФО «ОГМ» пытается направить план в ДТОиР
THEN система отклоняет запрос с ошибкой 400
AND статус плана остаётся «На проверке у ЦФО»

#### Scenario: Любой согласовавший ЦФО может направить в ДТОиР после полного согласования
GIVEN план направлен ЦФО «ОГМ» и «ОГС», оба согласовали
WHEN ЦФО «ОГС» (не последний принявший решение) направляет план в ДТОиР
THEN статус плана становится «На проверке ДТОиР»

### Requirement: Финальное решение ДТОиР
Система SHALL позволять только роли ДТОиР выносить финальное решение по
плану, находящемуся в статусе «На проверке ДТОиР»: согласование переводит
план в неизменяемый финальный статус «Согласовано», возврат требует хотя бы
одного открытого замечания от ДТОиР и переводит план в статус «Возвращён
ДТОиР».

#### Scenario: Согласованный план становится неизменяемым
GIVEN план в статусе «На проверке ДТОиР»
WHEN пользователь ДТОиР выносит решение «Согласовать»
THEN статус плана становится «Согласовано»
AND дальнейшая загрузка новых версий файлов для этого плана отклоняется с ошибкой 400

#### Scenario: Возврат ДТОиР требует хотя бы одного замечания
GIVEN план в статусе «На проверке ДТОиР» без открытых замечаний от ДТОиР
WHEN пользователь ДТОиР пытается вынести решение «Вернуть на доработку» без предварительно оставленного замечания
THEN система отклоняет запрос с ошибкой 400

#### Scenario: Филиал повторно направляет план в ДТОиР после доработки
GIVEN план в статусе «Возвращён ДТОиР»
WHEN Филиал-владелец повторно направляет план в ДТОиР
THEN статус плана становится «На проверке ДТОиР»

### Requirement: Видимость планов по ролям
Система SHALL ограничивать видимость планов ролью пользователя: Филиал видит
только планы своего филиала, ЦФО видит только планы, к которым у него есть
статус проверки, ДТОиР видит планы всех филиалов (аудит).

#### Scenario: Филиал не видит чужой план
GIVEN план PLN-000030 принадлежит филиалу «Херсонгаз»
WHEN пользователь роли Филиал, привязанный к филиалу «Запорожгаз», запрашивает карточку PLN-000030
THEN система отклоняет запрос с ошибкой 403

#### Scenario: ДТОиР видит планы всех филиалов
GIVEN в системе есть планы филиалов «Донбассгаз», «Луганскгаз», «Запорожгаз», «Херсонгаз»
WHEN пользователь роли ДТОиР запрашивает список планов без фильтра по филиалу
THEN система возвращает планы всех четырёх филиалов

### Requirement: Версии файлов плана не удаляются
Система SHALL сохранять каждую загруженную версию файла слота плана
бессрочно; загрузка новой версии SHALL добавлять запись версии, а не
изменять или удалять предыдущие.

#### Scenario: История версий слота сохраняет все загрузки
GIVEN слот «Пакет документов» плана уже имеет 2 версии файла
WHEN филиал загружает третью версию этого слота
THEN у слота становится 3 версии файла
AND первые две версии остаются доступными для просмотра/скачивания без изменений

### Requirement: Независимость домена плана от корректировки
Система SHALL хранить данные плана в собственных таблицах, не связанных
внешними ключами с таблицами домена «Корректировка», и SHALL NOT изменять
поведение или данные существующих корректировок при любых операциях над
планами.

#### Scenario: Удаление плана не затрагивает корректировки
GIVEN у филиала есть план в статусе «Черновик» и корректировка в статусе «На проверке у ЦФО»
WHEN филиал удаляет свой план
THEN корректировка остаётся без изменений в статусе «На проверке у ЦФО»
