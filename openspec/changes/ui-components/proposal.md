# ui-components

## Why

Базовые UI-примитивы в `apps/frontend/src/components/ui/` (обёртки над Base UI)
периодически требуют точечных визуальных и UX-правок — курсор, отступы, состояния
наведения — не связанных с конкретной продуктовой фичей и не затрагивающих ни один
существующий change. Без общего change такие правки либо привязываются к
случайному постороннему change, либо остаются без обязательного трейлера `Change`.

Это краткое техническое изменение: копится под общим `ui-components` change без
влияния на продуктовые capability, API-контракт или наблюдаемое поведение фич.
Delta specs не создаются.

## Backend

Не затрагивается — правки только в UI-примитивах фронтенда.

## Frontend

`apps/frontend/src/components/ui/select/select.tsx`:
- `SelectTrigger`: добавлен `cursor-pointer`, чтобы триггер визуально читался как
  интерактивный элемент.
- `SelectContent`: добавлены внутренние отступы (`p-4`) и вертикальный gap
  (`flex flex-col gap-3`) между пунктами списка вместо элементов, прижатых друг к
  другу.

## Влияние на качество

- Уровень риска: P3
- Затронутые маршруты: нет (переиспользуемый UI-примитив, ещё не подключён ни к
  одной странице)
- Затронутые frontend-компоненты: `apps/frontend/src/components/ui/select/select.tsx`
- Затронутые API: нет
- TDD-порядок: не применим — чисто визуальная правка без наблюдаемого поведения
- Обязательные уровни проверки: Static (`bun run lint`, `bun run typecheck`)
- Ручные проверки: визуальная проверка компонента в Storybook/странице при первом
  реальном использовании
- План отката: `git revert` коммита правки
