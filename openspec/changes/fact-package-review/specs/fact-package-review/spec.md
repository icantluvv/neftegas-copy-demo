## ADDED Requirements

### Requirement: Направления и каталог форм факт-пакета
Система SHALL предоставлять ровно четыре направления работ факта (ДО, ТОиР,
КР ПД, КР ХС) и каталог из семи форм документов, где направления ДО, ТОиР и
КР ПД включают все семь форм, а направление КР ХС SHALL NOT включать формы
приёмки работ у подрядчика (Акт выполнения услуги, форма КС-2, форма КС-3) —
только четыре формы: Акт выполнения работ, Акт вовлечённости материалов,
Счёт на оплату, Заявка на платёж.

#### Scenario: Каталог форм направления КР ХС сокращён
GIVEN пользователь роли Филиал открывает экран «Файлы» модуля «Факт»
WHEN он выбирает вкладку направления «КР ХС»
THEN система показывает ровно 4 формы каталога — без «Акт выполнения услуги», «Форма КС-2», «Форма КС-3»

#### Scenario: Каталог форм направлений ДО, ТОиР, КР ПД полный
GIVEN пользователь роли Филиал открывает экран «Файлы» модуля «Факт»
WHEN он выбирает вкладку направления «ДО», «ТОиР» либо «КР ПД»
THEN система показывает все 7 форм каталога

### Requirement: Факт-пакет по направлению создаётся заново каждый раз
Система SHALL создавать новый факт-пакет с новым человекочитаемым ID при
каждом обращении к действию «Создать» по направлению — по аналогии с
созданием корректировки; один филиал (или один ЦФО, см. «Факт-пакет,
созданный ЦФО») SHALL иметь возможность одновременно владеть несколькими
факт-пакетами одного направления. Повторная отправка после доработки
изменяет статус существующего факт-пакета и не создаёт новую сущность.

#### Scenario: Повторная отправка не создаёт новый факт-пакет
GIVEN факт-пакет FCT-000014 филиала «Донбассгаз» по направлению «КР ХС» в статусе «Возвращён на доработку»
WHEN филиал загружает новые версии форм и повторно направляет пакет на проверку
THEN система обновляет статус того же факт-пакета FCT-000014
AND человекочитаемый ID не меняется

#### Scenario: Экран «Файлы» всегда создаёт новый факт-пакет
GIVEN у филиала «Луганскгаз» уже есть факт-пакет по направлению «ТОиР» в статусе «Черновик»
WHEN филиал повторно открывает раздел «Файлы» и создаёт факт-пакет по направлению «ТОиР»
THEN система создаёт новый факт-пакет с новым человекочитаемым ID
AND ранее созданный факт-пакет по этому направлению остаётся без изменений

### Requirement: Факт-пакет, созданный ЦФО
Система SHALL позволять роли ЦФО создавать собственный факт-пакет по
направлению — без привязки к филиалу (`filialId` не заполнен, `cfoId`
заполнен), с тем же каталогом форм направления, что и у филиала. Такой
факт-пакет SHALL NOT проходить через проверку ЦФО (создавший ЦФО уже
выступает проверяющим по смыслу) — направление переводит его сразу в статус
«На проверке ДТОиР», минуя «На проверке у ЦФО»/«Согласовано всеми ЦФО».
Владение факт-пакетом, созданным ЦФО, ограничивается создавшим его ЦФО:
загружать формы, отмечать замечания исправленными и направлять в ДТОиР может
только пользователь этого же ЦФО.

#### Scenario: ЦФО создаёт свой факт-пакет и направляет сразу в ДТОиР
GIVEN пользователь роли ЦФО «ОГМ» создаёт факт-пакет по направлению «ДО»
WHEN он загружает форму и вызывает направление без выбора ЦФО
THEN статус факт-пакета становится «На проверке ДТОиР», минуя проверку ЦФО

#### Scenario: Чужой ЦФО не может загрузить форму в пакет другого ЦФО
GIVEN факт-пакет создан пользователем ЦФО «ОГС»
WHEN пользователь ЦФО «ОГМ» пытается загрузить версию формы в этот факт-пакет
THEN система отклоняет запрос с ошибкой 403

### Requirement: Направление факт-пакета на проверку ЦФО
Система SHALL разрешать направление факт-пакета на проверку независимо от
комплектации каталога направления — с любым числом загруженных форм, включая
ноль, и только выбранным из состава `FilialCFO` центрам финансовой
ответственности (ЦФО), связанным с филиалом-автором. Полная комплектация не
является условием направления — филиал направляет столько форм, сколько
успел загрузить на момент отправки.

#### Scenario: Направление доступно при неполном пакете
GIVEN факт-пакет направления «ДО» в статусе «Черновик», в котором форма «Счёт на оплату» не имеет ни одной версии
WHEN филиал вызывает направление факт-пакета на проверку выбранному ЦФО
THEN система принимает запрос и переводит факт-пакет в статус «На проверке ЦФО»

#### Scenario: Направление ЦФО, не связанному с филиалом, отклоняется
GIVEN факт-пакет филиала «Херсонгаз», полностью укомплектованный
AND ЦФО «АНГНКС» не связан с филиалом «Херсонгаз» через FilialCFO
WHEN филиал пытается направить факт-пакет ЦФО «АНГНКС»
THEN система отклоняет запрос с ошибкой 400
AND не создаёт статус проверки для этого ЦФО

#### Scenario: Успешное направление на проверку нескольким ЦФО
GIVEN факт-пакет филиала «Запорожгаз» по направлению «КР ПД» полностью укомплектован
AND ЦФО «ОГМ» и «ОГС» связаны с филиалом «Запорожгаз» через FilialCFO
WHEN филиал направляет факт-пакет на проверку, выбрав ЦФО «ОГМ» и «ОГС»
THEN статус факт-пакета становится «На проверке у ЦФО»
AND для каждого выбранного ЦФО атомарно создаётся независимый статус проверки со значением «Ожидает решения»

### Requirement: Замечания к форме факт-пакета
Система SHALL разрешать оставить замечание к форме факт-пакета только
проверяющему, для которого этот факт-пакет в данный момент находится на
проверке (ЦФО — пока его статус проверки «Ожидает решения»; ДТОиР — пока
факт-пакет в статусе «На проверке ДТОиР»), и SHALL атомарно переводить
факт-пакет и статус проверки автора замечания в состояние возврата на
доработку.

#### Scenario: ЦФО не может оставить замечание после принятого решения
GIVEN факт-пакет на проверке у ЦФО «СИУС», статус проверки ЦФО «СИУС» уже «Согласовано»
WHEN пользователь ЦФО «СИУС» пытается оставить замечание к форме этого факт-пакета
THEN система отклоняет запрос с ошибкой 400
AND статус факт-пакета не меняется

#### Scenario: Замечание ЦФО переводит пакет в доработку
GIVEN факт-пакет на проверке у ЦФО «ПОА» со статусом проверки «Ожидает решения»
WHEN пользователь ЦФО «ПОА» оставляет замечание к форме «Счёт на оплату» этого факт-пакета
THEN статус факт-пакета становится «Возвращён на доработку»
AND статус проверки ЦФО «ПОА» становится «Возвращено»
AND статус проверки ЦФО, не оставившего замечание, если он был согласовавшим ранее, не изменяется

#### Scenario: ДТОиР не может оставить замечание вне своей проверки
GIVEN факт-пакет в статусе «Ожидает отправки в ДТОиР» (ещё не направлен в ДТОиР)
WHEN пользователь ДТОиР пытается оставить замечание к форме этого факт-пакета
THEN система отклоняет запрос с ошибкой 400

### Requirement: Отметка замечания исправленным и удаление замечания
Система SHALL позволять только филиалу-владельцу факт-пакета отмечать
собственные полученные замечания как исправленные, и SHALL разрешать
удаление замечания только его автору и только пока замечание в статусе
«Открыто».

#### Scenario: Филиал отмечает замечание исправленным
GIVEN замечание REM-000201 к форме факт-пакета филиала «Донбассгаз» в статусе «Открыто»
WHEN филиал «Донбассгаз» загружает исправленную версию формы и отмечает замечание REM-000201 исправленным
THEN статус замечания REM-000201 становится «Исправлено филиалом»

#### Scenario: Чужой автор не может удалить замечание
GIVEN замечание REM-000202 оставлено ЦФО «ОГЭ» в статусе «Открыто»
WHEN пользователь ЦФО «ПОЗК» пытается удалить замечание REM-000202
THEN система отклоняет запрос с ошибкой 403
AND замечание REM-000202 остаётся в системе

#### Scenario: Автор не может удалить закрытое замечание
GIVEN замечание REM-000203, оставленное ДТОиР, уже в статусе «Закрыто»
WHEN автор замечания (пользователь ДТОиР) пытается удалить REM-000203
THEN система отклоняет запрос с ошибкой 400
AND замечание REM-000203 остаётся неизменным

### Requirement: Повторная отправка после доработки без сброса истории согласовавших ЦФО
Система SHALL разрешать повторное направление факт-пакета на проверку только
когда все замечания от ЦФО, вернувших его, отмечены филиалом как
исправленные, и SHALL NOT сбрасывать статус согласования ранее одобривших
ЦФО при повторном направлении другому ЦФО.

#### Scenario: Повторная отправка блокируется неисправленными замечаниями
GIVEN факт-пакет в статусе «Возвращён на доработку», у которого замечание REM-000210 всё ещё «Открыто»
WHEN филиал пытается повторно направить факт-пакет на проверку
THEN система отклоняет запрос с ошибкой 400

#### Scenario: Статус согласовавшего ранее ЦФО не сбрасывается
GIVEN факт-пакет, у которого ЦФО «ОГМ» уже согласовал (статус «Согласовано»), а ЦФО «ОГС» вернул с замечанием
WHEN филиал исправляет замечания ЦФО «ОГС» и повторно направляет факт-пакет только ЦФО «ОГС»
THEN статус проверки ЦФО «ОГС» становится «Ожидает решения»
AND статус проверки ЦФО «ОГМ» остаётся «Согласовано»

### Requirement: Направление факт-пакета в ДТОиР
Система SHALL разрешать направление факт-пакета на финальную проверку ДТОиР
только когда все обязательные (выбранные при направлении) ЦФО находятся в
статусе «Согласовано», и SHALL предоставлять действие «Направить в ДТОиР»
каждому согласовавшему ЦФО этого факт-пакета, а не только последнему
принявшему решение.

#### Scenario: Направление в ДТОиР недоступно до согласования всех ЦФО
GIVEN факт-пакет направлен ЦФО «ОГМ» и «ОГС», ЦФО «ОГМ» согласовал, ЦФО «ОГС» ещё не принял решение
WHEN ЦФО «ОГМ» пытается направить факт-пакет в ДТОиР
THEN система отклоняет запрос с ошибкой 400
AND статус факт-пакета остаётся «На проверке у ЦФО»

#### Scenario: Любой согласовавший ЦФО может направить в ДТОиР после полного согласования
GIVEN факт-пакет направлен ЦФО «ОГМ» и «ОГС», оба согласовали
WHEN ЦФО «ОГС» (не последний принявший решение) направляет факт-пакет в ДТОиР
THEN статус факт-пакета становится «На проверке ДТОиР»

### Requirement: Финальное решение ДТОиР
Система SHALL позволять только роли ДТОиР выносить финальное решение по
факт-пакету, находящемуся в статусе «На проверке ДТОиР»: согласование
переводит факт-пакет в неизменяемый финальный статус «Согласовано», возврат
требует хотя бы одного открытого замечания от ДТОиР и переводит факт-пакет в
статус «Возвращён ДТОиР».

#### Scenario: Согласованный факт-пакет становится неизменяемым
GIVEN факт-пакет в статусе «На проверке ДТОиР»
WHEN пользователь ДТОиР выносит решение «Согласовать»
THEN статус факт-пакета становится «Согласовано»
AND дальнейшая загрузка новых версий форм для этого факт-пакета отклоняется с ошибкой 400

#### Scenario: Возврат ДТОиР требует хотя бы одного замечания
GIVEN факт-пакет в статусе «На проверке ДТОиР» без открытых замечаний от ДТОиР
WHEN пользователь ДТОиР пытается вынести решение «Вернуть на доработку» без предварительно оставленного замечания
THEN система отклоняет запрос с ошибкой 400

### Requirement: Видимость факт-пакетов по ролям
Система SHALL ограничивать видимость факт-пакетов ролью пользователя: Филиал
видит только факт-пакеты своего филиала, ЦФО видит факт-пакеты, направленные
его ЦФО на проверку, и собственные факт-пакеты, созданные этим ЦФО, ДТОиР
видит факт-пакеты всех филиалов и ЦФО (аудит).

#### Scenario: Филиал не видит чужой факт-пакет
GIVEN факт-пакет FCT-000030 принадлежит филиалу «Херсонгаз»
WHEN пользователь роли Филиал, привязанный к филиалу «Запорожгаз», запрашивает карточку FCT-000030
THEN система отклоняет запрос с ошибкой 403

#### Scenario: ДТОиР видит факт-пакеты всех филиалов
GIVEN в системе есть факт-пакеты филиалов «Донбассгаз», «Луганскгаз», «Запорожгаз», «Херсонгаз»
WHEN пользователь роли ДТОиР запрашивает список факт-пакетов без фильтра по филиалу
THEN система возвращает факт-пакеты всех четырёх филиалов

### Requirement: Версии файлов формы не удаляются
Система SHALL сохранять каждую загруженную версию файла формы факт-пакета
бессрочно; загрузка новой версии SHALL добавлять запись версии, а не
изменять или удалять предыдущие.

#### Scenario: История версий формы сохраняет все загрузки
GIVEN форма «Акт выполнения работ» факт-пакета уже имеет 2 версии файла
WHEN филиал загружает третью версию этой формы
THEN у формы становится 3 версии файла
AND первые две версии остаются доступными для просмотра/скачивания без изменений
