## Context

`apps/frontend/src/components/notification-bell/notification-bell.tsx` уже
опрашивает `useGetNotifications({ query: { refetchInterval: 60_000 } })` и
уже использует `useMarkAllNotificationsRead` на странице `/notifications`
(`apps/frontend/app/(private)/notifications/components/notifications-content.tsx`,
из `notifications-center`) — тот же мутационный хук переиспользован здесь для
кнопки внутри панели.

## Разрешённый конфликт с `notifications-center` (архивирован)

Ранее в этом change пользователь запросил кнопку «Отметить все прочитанными»
обратно в панель, что противоречило требованию «Содержимое выпадающей панели
уведомлений» из `notifications-center` (`SHALL NOT` для этой кнопки в
панели). На тот момент `notifications-center` ещё не был заархивирован, и
конфликт был оставлен как блокер (см. историю задачи 4.1 в `tasks.md`).

`notifications-center` с тех пор заархивирован (`openspec/specs/notifications/spec.md`
— базовая спека, содержит тот же `SHALL NOT`). В этой сессии пользователь
запросил редизайн попапа и явно попросил убрать кнопку «Отметить все
прочитанными» и число непрочитанных из заголовка — решение окончательно
пересмотрено в пользу исходного `SHALL NOT`. Конфликт снят: реализация
приведена в соответствие с базовой спекой, добавлен `MODIFIED Requirements`
в `specs/notifications/spec.md` этого change для части про заголовок (число
непрочитанных больше не отображается — этого не было в исходном требовании
`notifications-center`).

### Редизайн попапа панели уведомлений

По прямому запросу пользователя:
- Внутренний отступ попапа уменьшен (`p-6` → `p-3`) — меньше «воздуха» от
  краёв контейнера.
- Кнопка-колокольчик в шапке увеличена до `size-12` (был `icon-lg`, `size-9`).
- Заголовок «Уведомления» больше не показывает число непрочитанных в скобках.
- Кнопка «Отметить все прочитанными» убрана из панели окончательно.
- Ссылка «Все уведомления» оформлена как кнопка (`buttonVariants({variant:
  "secondary"})`, `min-h-12`) на всю ширину контейнера в нижней части попапа
  — клик должен приходиться на всю кнопку, а не только на текст ссылки; сама
  навигация (`<Link href="/notifications">`) не меняется, меняется только
  визуальное оформление и кликабельная область.
- Между датой и временем записи в списке (`notification-panel-list.tsx`)
  увеличен визуальный зазор: строка `formatNotificationDateTime(...)`
  разбивается на `[datePart, timePart]` локально в компоненте (`.split(" ")`)
  и рендерится в двух `<span>` с `gap-2` вместо одиночного пробела в тексте.
  Сама `formatNotificationDateTime` в `#/utils/format-notification-date-time.ts`
  не менялась — она переиспользуется в `correction-header.tsx`,
  `cfo-statuses.tsx` и `package-completeness.tsx`, где нужна именно строка;
  менять её сигнатуру ради одного места использования нецелесообразно.

## Goals / Non-Goals

**Goals:**
- Уведомлять пользователя о новых непрочитанных записях, даже если вкладка не
  в фокусе, без изменения существующего API.
- Не показывать «задним числом» уже существующие на момент открытия вкладки
  непрочитанные уведомления как «новые» — иначе при каждой перезагрузке
  страницы пользователь получал бы лавину системных уведомлений о давно
  известных событиях.

**Non-Goals:**
- Push-уведомления при закрытом браузере (Service Worker + Web Push) — не
  входит, см. `proposal.md`.
- Настройка пользователем (вкл/выкл) показа системных уведомлений отдельно от
  браузерного разрешения — не запрашивалась.

## Decisions

### Диф по `Set<id>` в `useRef`, без персистентности между перезагрузками

`useDesktopNotifications` хранит `Set` увиденных id в `useRef` (не
`localStorage`) — при перезагрузке страницы весь текущий список считается
«базовым» и не порождает уведомлений. Отклонено: персистентность в
`localStorage` дала бы уведомления о событиях, случившихся, пока вкладка была
полностью закрыта — что противоречит собственному условию пользователя
(«лишь бы был открыт [браузер с вкладкой]», то есть контракт не
предполагает пропущенных при закрытой вкладке событий как обязанность этой
фичи).

### Разрешение запрашивается при монтировании, не по клику

`Notification.requestPermission()` вызывается в `useEffect` при первом
рендере `NotificationBell`, а не по явному действию пользователя (кнопка
«Включить уведомления» не вводится) — минимальный интерфейс, соответствует
формулировке запроса. Компромисс: некоторые браузеры (Chrome) могут
приглушать автоматический запрос разрешения эвристикой анти-спама после
повторных отказов пользователя — не обрабатывается отдельно, стандартное
поведение браузера.
