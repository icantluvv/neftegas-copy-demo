## Why

Колокольчик уведомлений (`NotificationBell`, реализован в change
`notifications-center`) опрашивает `GET /notifications` раз в 60 секунд, но
узнать о новом уведомлении можно только открыв саму вкладку и посмотрев на
бейдж — если пользователь свернул окно браузера или переключился на другое
приложение, событие (например, возврат корректировки с замечанием) остаётся
незамеченным до следующего раза, когда он вернётся к вкладке. Пользователь
запросил системные (ОС) всплывающие уведомления, которые появляются в углу
экрана независимо от того, активна ли вкладка браузера — единственное условие
работы: вкладка с приложением должна быть открыта (даже свёрнута).

## What Changes

- Добавляется системное (Web Notification API) уведомление при обнаружении
  новых непрочитанных записей на каждом опросе `GET /notifications` (раз в 60
  секунд, тот же таймер, что уже использует `NotificationBell`). Разрешение на
  показ системных уведомлений запрашивается при монтировании колокольчика.
  Первый опрос после монтирования не считается «новым» (нет уведомлений при
  первой загрузке страницы) — уведомляются только записи, появившиеся в
  последующих опросах. Клик по системному уведомлению фокусирует вкладку,
  помечает запись прочитанной и переводит на карточку соответствующей
  корректировки.
- **Ранее в этом change** кнопка «Отметить все прочитанными» была добавлена в
  панель по прямому запросу пользователя, что на тот момент противоречило
  требованию «Содержимое выпадающей панели уведомлений» уже заархивированного
  `notifications-center` (`SHALL NOT` для этой кнопки внутри панели). **В этой
  сессии решение пересмотрено повторно**: пользователь запросил редизайн
  попапа — кнопка «Отметить все прочитанными» и число непрочитанных в
  заголовке убраны из панели, ссылка «Все уведомления» превращена в кнопку на
  всю ширину контейнера внизу панели, уменьшены отступы от краёв. Тем самым
  реализация приведена в соответствие с базовой спекой в части кнопки массовой
  пометки и формально модифицирует её же в части заголовка (число
  непрочитанных больше не отображается) — см. `specs/notifications/spec.md`
  (MODIFIED) и `design.md`.

## Capabilities

### New Capabilities

- `desktop-notifications`: системные уведомления ОС о новых непрочитанных
  записях, обнаруженных фоновым опросом.

### Modified Capabilities

- `notifications`: требование «Содержимое выпадающей панели уведомлений» —
  заголовок панели больше не показывает число непрочитанных, кнопка
  «Отметить все прочитанными» окончательно убрана из панели, ссылка «Все
  уведомления» оформлена как кнопка на всю ширину контейнера. См.
  `specs/notifications/spec.md`.

## Impact

- **Frontend**: новый `apps/frontend/src/hooks/use-desktop-notifications.ts`;
  `apps/frontend/src/components/notification-bell/notification-bell.tsx`
  дополнен подключением хука; кнопка «Отметить все прочитанными» и число
  непрочитанных в заголовке панели убраны, `useMarkAllNotificationsRead`
  больше не используется в `NotificationBell` (остаётся на странице
  `/notifications`), ссылка «Все уведомления» оформлена как кнопка на всю
  ширину контейнера, уменьшены внутренние отступы попапа;
  `apps/frontend/src/components/notification-bell/notification-panel-list.tsx`
  и `apps/frontend/src/utils/format-notification-date-time.ts` — увеличен
  визуальный зазор между датой и временем записи.
- **Backend**: не затронут — используется существующий `GET /notifications`
  без изменений.
- **API-контракт**: не менялся.
- **Внешние зависимости**: не вводятся — используется нативный браузерный
  `Notification` API, доступный без установки пакетов.
- **Вне области**: push-уведомления при закрытой вкладке/браузере (Web Push +
  Service Worker) — нативный `Notification` API работает только пока вкладка
  открыта, что явно устраивает пользователя по формулировке запроса
  («неважно, сидишь ли в нём, главное чтобы было включено» — трактовано как
  «вкладка открыта, необязательно активна»).

## Влияние на качество

- **Уровень риска**: P2 — точечное дополнение существующего, уже работающего
  компонента (`NotificationBell`), без изменения API, прав доступа или
  статусной модели; риск сосредоточен в конфликте с `notifications-center»
  (см. выше), а не в самой механике уведомлений.
- **Затронутые маршруты**: ни один напрямую — `NotificationBell` смонтирован
  в `apps/frontend/app/(private)/layout.tsx`, виден на всех приватных
  страницах без изменений маршрутизации.
- **Затронутые frontend-компоненты**: `NotificationBell`, новый
  `useDesktopNotifications`.
- **Затронутые backend-модули**: нет.
- **Затронутые API**: нет (переиспользуется `GET /notifications`).
- **TDD-порядок**: не соблюдён — реализация без предварительных тестов (см.
  `test-plan.md`, Gaps).
- **Обязательные уровни проверки**: Static (`tsc --noEmit`, `eslint`) —
  выполнены, 0 ошибок. Frontend Component/E2E — не выполнены (см. Gaps).
- **Ручные проверки или waiver**: показ системного уведомления в реальном ОС
  и клик по нему — не проверены вручную в этой сессии (нет доступа к GUI из
  среды агента); логика диффа «уже виденных» id проверена только чтением
  кода/typecheck. Явный waiver с высоким приоритетом устранения — см.
  `test-plan.md`.
- **План отката**: изменения аддитивны для `desktop-notifications`
  (обёрточный хук, не влияет на существующую логику при `Notification`
  недоступном в среде — есть явная проверка `"Notification" in window`).
  Кнопку в панели откатить проще — точечный revert одного JSX-блока и импорта
  `useMarkAllNotificationsRead`.
