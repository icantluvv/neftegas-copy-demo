## Purpose

Даёт филиалу-автору исправить ошибочно выбранный при создании тип
корректировки, пока пакет ещё не направлен на проверку, без необходимости
удалять черновик и создавать его заново.

## ADDED Requirements

### Requirement: Доступ к форме смены типа

Система SHALL предоставлять маршрут `/corrections/{humanId}/edit` только
пользователю, являющемуся автором-филиалом этой корректировки, и только
пока корректировка находится в статусе `DRAFT`. Во всех остальных случаях
(чужая корректировка, любая другая роль, любой другой статус, включая
прямой ввод адреса) система SHALL отображать экран «Доступ запрещён».

#### Scenario: Автор открывает форму смены типа своего черновика
- **GIVEN** пользователь роли FILIAL — автор корректировки в статусе `DRAFT`
- **WHEN** пользователь открывает `/corrections/{humanId}/edit`
- **THEN** система отображает форму с текущим типом корректировки, выбранным в списке

#### Scenario: Форма недоступна после направления на проверку
- **GIVEN** корректировка автора в статусе, отличном от `DRAFT`
- **WHEN** автор открывает `/corrections/{humanId}/edit` напрямую по адресу
- **THEN** система отображает экран «Доступ запрещён»

#### Scenario: Форма недоступна другой роли и чужому филиалу
- **WHEN** пользователь роли CFO, ДТОиР или FILIAL другого филиала открывает `/corrections/{humanId}/edit` любой корректировки, автором которой он не является
- **THEN** система отображает экран «Доступ запрещён»

### Requirement: Единственное поле формы — тип корректировки

Форма SHALL содержать ровно одно поле — выпадающий список типов
корректировки из справочника, предзаполненный текущим типом, кнопку
«Сохранить» и кнопку «Отмена», ведущую обратно на карточку корректировки без
изменений.

#### Scenario: Сохранение того же типа не выполняет действие
- **GIVEN** форма открыта с текущим типом, выбранным по умолчанию
- **WHEN** пользователь нажимает «Сохранить», не меняя выбор
- **THEN** кнопка «Сохранить» неактивна для уже выбранного текущего типа

### Requirement: Реконсиляция слотов пакета при смене типа

При успешной смене типа система SHALL удалить все слоты пакета, привязанные
к прежнему типу (кроме общего слота «Excel корректировка», который от типа
не зависит), вместе со всеми загруженными в них версиями файлов, и SHALL
создать новые слоты по составу требований нового типа — тем же алгоритмом,
что при создании корректировки. Общий слот «Excel корректировка» и его
версии файлов SHALL сохраняться без изменений.

#### Scenario: Смена типа удаляет слоты и файлы прежнего типа
- **GIVEN** черновик типа A с загруженной версией файла в одном из типозависимых слотов
- **WHEN** автор меняет тип на B
- **THEN** слоты типа A и загруженная в них версия файла удаляются
- **AND** создаются новые пустые слоты по составу требований типа B
- **AND** версия файла в общем слоте «Excel корректировка», если она была, сохраняется

#### Scenario: Смена на тот же тип не изменяет данные
- **GIVEN** черновик типа A
- **WHEN** сервер получает запрос на смену типа на тот же тип A
- **THEN** система не удаляет и не создаёт ни одного слота
- **AND** возвращает текущую карточку без изменений

### Requirement: Guard-условия смены типа на бэкенде

Система SHALL отклонять запрос на смену типа с кодом `403`, если инициатор —
не автор-филиал корректировки, с кодом `400`, если статус корректировки не
`DRAFT`, и с кодом `404`, если указанный `correctionTypeId` не существует.
Проверка SHALL выполняться на бэкенде независимо от того, скрыта ли кнопка
на фронтенде.

#### Scenario: Бэкенд отклоняет смену типа у направленной корректировки
- **GIVEN** корректировка в статусе `UNDER_CFO_REVIEW`
- **WHEN** её автор отправляет запрос на смену типа напрямую к API, в обход интерфейса
- **THEN** сервер отвечает `400` и не изменяет ни тип, ни слоты корректировки
