## Purpose

Обеспечивает server-side управление сессиями пользователя: выдачу сессии при
успешном входе, продление её при активности, немедленное и полное завершение
доступа по запросу пользователя — для одной сессии или для всех сессий сразу.

## ADDED Requirements

### Requirement: Выдача сессии при успешном входе

Система SHALL создавать новую server-side сессию при каждом успешном
`POST /auth/login` и SHALL передавать её идентификатор клиенту в единой httpOnly
cookie `session_id`. Система SHALL NOT возвращать идентификатор сессии в теле
ответа или в любом другом виде, читаемом клиентским JavaScript.

#### Scenario: Успешный вход создаёт сессию
- **GIVEN** пользователь ввёл верные email и пароль
- **WHEN** запрос `POST /auth/login` завершается успешно
- **THEN** ответ содержит `Set-Cookie` с httpOnly-cookie `session_id`
- **AND** cookie не содержит атрибут, разрешающий доступ из JavaScript (`httpOnly=true`)

#### Scenario: Повторный вход создаёт независимую новую сессию
- **GIVEN** у пользователя уже есть одна активная сессия
- **WHEN** пользователь успешно входит повторно с другого клиента
- **THEN** система создаёт вторую независимую сессию
- **AND** первая сессия остаётся активной и не завершается автоматически

### Requirement: Доступ к защищённым ручкам по действующей сессии

Система SHALL предоставлять доступ к защищённым (не помеченным как публичные)
HTTP-ручкам только при наличии действующей сессии, соответствующей
идентификатору из cookie `session_id`. Система SHALL отвечать `401 Unauthorized`,
если cookie отсутствует, либо не соответствует ни одной действующей сессии.

#### Scenario: Запрос с действующей сессией проходит
- **GIVEN** пользователь успешно вошёл и получил cookie `session_id`
- **WHEN** пользователь отправляет запрос к защищённой ручке с этой cookie
- **THEN** система обрабатывает запрос от имени этого пользователя

#### Scenario: Запрос без cookie отклоняется
- **WHEN** запрос к защищённой ручке отправлен без cookie `session_id`
- **THEN** система отвечает `401 Unauthorized`

#### Scenario: Запрос с несуществующей или уже завершённой сессией отклоняется
- **GIVEN** cookie `session_id` содержит значение, не соответствующее ни одной
  действующей сессии (никогда не существовавшей или уже завершённой)
- **WHEN** пользователь отправляет запрос к защищённой ручке с этой cookie
- **THEN** система отвечает `401 Unauthorized`

### Requirement: Продление сессии при активности (sliding TTL)

Система SHALL продлевать срок действия сессии до полного окна неактивности
(10 часов) при каждом успешном запросе с действующей сессией. Система SHALL
завершать сессию автоматически, если с последнего успешного запроса прошло
больше этого окна.

#### Scenario: Активность продлевает сессию
- **GIVEN** пользователь вошёл в систему и с момента входа прошло менее 10 часов бездействия
- **WHEN** пользователь отправляет запрос к защищённой ручке с действующей сессией
- **THEN** окно бездействия сессии отсчитывается заново от момента этого запроса

#### Scenario: Бездействие дольше окна завершает сессию
- **GIVEN** пользователь вошёл в систему
- **WHEN** с момента последнего запроса пользователя прошло больше 10 часов без единого запроса
- **THEN** следующий запрос с cookie этой сессии получает `401 Unauthorized`

### Requirement: Завершение текущей сессии (logout)

Система SHALL завершать сессию, соответствующую переданной cookie `session_id`,
при запросе `POST /auth/logout`, и SHALL инструктировать клиента удалить эту
cookie. Система SHALL NOT затрагивать другие активные сессии того же
пользователя при завершении одной сессии.

#### Scenario: Logout завершает только текущую сессию
- **GIVEN** у пользователя есть две активные сессии (например, с двух устройств)
- **WHEN** пользователь отправляет `POST /auth/logout` с cookie первой сессии
- **THEN** первая сессия перестаёт давать доступ (последующий запрос с её cookie получает `401 Unauthorized`)
- **AND** вторая сессия остаётся действующей

### Requirement: Завершение всех сессий пользователя (logout-all)

Система SHALL завершать все активные сессии текущего пользователя, включая
сессию, из которой выполнен запрос, при запросе `POST /auth/logout-all`.
Запрос SHALL требовать действующую сессию (не является публичной ручкой).

#### Scenario: Logout-all завершает все сессии пользователя
- **GIVEN** у пользователя есть две и более активных сессий с разных устройств
- **WHEN** пользователь отправляет `POST /auth/logout-all` с cookie одной из этих сессий
- **THEN** все сессии этого пользователя перестают давать доступ (каждый последующий запрос с их cookie получает `401 Unauthorized`)

#### Scenario: Logout-all не затрагивает сессии других пользователей
- **GIVEN** активны сессии двух разных пользователей
- **WHEN** первый пользователь отправляет `POST /auth/logout-all`
- **THEN** сессии второго пользователя остаются действующими

### Requirement: Учёт блокировки и деактивации учётной записи в рамках действующей сессии

Система SHALL отклонять запросы с действующей сессией, если связанная учётная
запись пользователя на момент запроса деактивирована (`isActive = false`) или
заблокирована (`isLocked = true`), даже если сама сессия ещё не истекла и не
была явно завершена.

#### Scenario: Деактивация учётной записи блокирует доступ по живой сессии
- **GIVEN** у пользователя есть действующая сессия
- **WHEN** администратор деактивирует учётную запись этого пользователя
- **AND** пользователь отправляет следующий запрос к защищённой ручке с той же cookie
- **THEN** система отвечает `401 Unauthorized`
