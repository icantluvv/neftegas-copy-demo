## Purpose

Даёт роли «Филиал» обзор своих корректировок на `/dashboard` (плитки
статистики, распределение по этапам, список) и путь к созданию новой
корректировки (`/corrections/create`), закрывая задачи 1–3 из ЧТЗ «Кабинет
Филиала» (`docs/tz/filial-cabinet.md`).

## ADDED Requirements

### Requirement: Плитки статистики на дашборде филиала

Система SHALL отображать на `/dashboard` для роли FILIAL 4 плитки статистики —
«Всего», «На проверке», «Возвращено», «Согласовано ДТОиР» — с данными из
`GET /corrections/stats/filial`. Плитка «На проверке» SHALL отображать значение
жёлтым цветом, плитка «Возвращено» SHALL отображать значение красным цветом,
плитка «Согласовано ДТОиР» SHALL отображать значение зелёным цветом.

#### Scenario: Плитки показывают статистику филиала

- **GIVEN** авторизован пользователь роли FILIAL
- **WHEN** пользователь открывает `/dashboard`
- **THEN** система отображает 4 плитки: «Всего», «На проверке», «Возвращено», «Согласовано ДТОиР»
- **AND** значение плитки «На проверке» отображается жёлтым цветом
- **AND** значение плитки «Возвращено» отображается красным цветом
- **AND** значение плитки «Согласовано ДТОиР» отображается зелёным цветом

### Requirement: Распределение корректировок по этапам на дашборде филиала

Система SHALL отображать на `/dashboard` для роли FILIAL донат-график
распределения собственных корректировок филиала по 4 укрупнённым группам
статуса — «Черновик», «В работе» (`UNDER_CFO_REVIEW`, `PARTIALLY_APPROVED`,
`RESUBMITTED`, `UNDER_DTOE_REVIEW`, `ALL_CFO_APPROVED`, `SENT_TO_DTOE`),
«Возвращено» (`RETURNED_FOR_REVISION`, `RETURNED_BY_DTOE`), «Согласовано»
(`APPROVED_BY_DTOE`) — с легендой (цвет, название группы, число) и общим
числом в центре графика.

#### Scenario: График показывает 4 группы с числом каждой

- **GIVEN** у филиала есть корректировки в разных статусах
- **WHEN** пользователь открывает `/dashboard`
- **THEN** система отображает донат-график с сегментами по группам «Черновик», «В работе», «Возвращено», «Согласовано»
- **AND** легенда справа показывает название каждой группы и число корректировок в ней
- **AND** в центре графика отображается общее число корректировок филиала

### Requirement: Фильтр таблицы корректировок по укрупнённой группе

Система SHALL предоставлять на `/dashboard` для роли FILIAL выпадающий список
«Фильтр по статусу» со значением по умолчанию «— все статусы —» и списком из 4
укрупнённых групп (см. Requirement «Распределение корректировок по этапам на
дашборде филиала»), ограничивающий таблицу корректировок записями выбранной
группы без нового запроса к серверу. Клик по сегменту графика или строке
легенды SHALL устанавливать соответствующее значение в этом же фильтре;
повторный клик по тому же сегменту SHALL возвращать фильтр к значению
«— все статусы —».

#### Scenario: Выбор группы в фильтре сужает таблицу

- **GIVEN** у филиала есть корректировки в статусах «Черновик» и «Возвращено на доработку»
- **WHEN** пользователь выбирает в фильтре значение «Возвращено»
- **THEN** таблица показывает только корректировки в статусах группы «Возвращено»

#### Scenario: Клик по сегменту графика выставляет фильтр

- **GIVEN** пользователь находится на `/dashboard`
- **WHEN** пользователь кликает по сегменту «В работе» на графике
- **THEN** фильтр принимает значение «В работе»
- **AND** таблица показывает только корректировки этой группы

#### Scenario: Повторный клик по тому же сегменту сбрасывает фильтр

- **GIVEN** фильтр установлен в значение «Возвращено» кликом по сегменту графика
- **WHEN** пользователь повторно кликает по тому же сегменту «Возвращено»
- **THEN** фильтр возвращается к значению «— все статусы —»
- **AND** таблица показывает корректировки всех статусов

### Requirement: Таблица «Мои корректировки»

Система SHALL отображать на `/dashboard` для роли FILIAL таблицу собственных
корректировок филиала с колонками «ID», «Тип», «Статус» (цветной бейдж),
«Этап», «Создано», «Изменено» и кнопкой «Открыть» в каждой строке,
переводящей на карточку `/corrections/{humanId}`. При отсутствии
корректировок у филиала SHALL отображаться вместо графика, фильтра и таблицы
текст «У вас пока нет корректировок» и кнопка «Создать первую корректировку».

#### Scenario: Таблица показывает список корректировок филиала

- **GIVEN** у филиала есть 2 корректировки
- **WHEN** пользователь открывает `/dashboard`
- **THEN** таблица показывает обе корректировки с колонками ID, Тип, Статус, Этап, Создано, Изменено
- **AND** каждая строка содержит кнопку «Открыть»

#### Scenario: Кнопка «Открыть» переходит на карточку корректировки

- **GIVEN** в таблице есть корректировка COR-000001
- **WHEN** пользователь нажимает «Открыть» в строке COR-000001
- **THEN** система переходит на маршрут `/corrections/COR-000001`

#### Scenario: Пустое состояние при отсутствии корректировок

- **GIVEN** у филиала нет ни одной корректировки
- **WHEN** пользователь открывает `/dashboard`
- **THEN** система отображает текст «У вас пока нет корректировок» и кнопку «Создать первую корректировку» вместо графика, фильтра и таблицы

### Requirement: Кнопка «Создать корректировку» на дашборде филиала

Система SHALL отображать на `/dashboard` для роли FILIAL кнопку «+ Создать
корректировку» рядом с фильтром, переводящую на маршрут `/corrections/create`.

#### Scenario: Кнопка ведёт на экран создания

- **GIVEN** пользователь роли FILIAL находится на `/dashboard`
- **WHEN** пользователь нажимает «+ Создать корректировку»
- **THEN** система переходит на маршрут `/corrections/create`

### Requirement: Экран создания корректировки

Система SHALL предоставлять маршрут `/corrections/create`, доступный только
роли FILIAL (прочим ролям SHALL отображать экран «Доступ запрещён»), с
единственным обязательным полем «Тип корректировки» (выпадающий список из
`GET /org/correction-types`). Кнопка «Создать» SHALL быть неактивна, пока тип
не выбран, и SHALL создавать корректировку (`POST /corrections`) и переводить
на карточку созданной корректировки при нажатии. Кнопка «Отмена» SHALL
возвращать на `/dashboard` без создания записи.

#### Scenario: Кнопка «Создать» неактивна без выбранного типа

- **GIVEN** пользователь роли FILIAL находится на `/corrections/create`
- **AND** тип корректировки не выбран
- **WHEN** пользователь пытается нажать «Создать»
- **THEN** кнопка «Создать» неактивна

#### Scenario: Создание корректировки переводит на её карточку

- **GIVEN** пользователь роли FILIAL находится на `/corrections/create`
- **AND** выбран тип корректировки «Стандартная корректировка программы»
- **WHEN** пользователь нажимает «Создать»
- **THEN** система создаёт корректировку в статусе «Черновик»
- **AND** переводит пользователя на карточку созданной корректировки

#### Scenario: Кнопка «Отмена» возвращает без создания

- **GIVEN** пользователь роли FILIAL находится на `/corrections/create`
- **WHEN** пользователь нажимает «Отмена»
- **THEN** система переходит на `/dashboard`
- **AND** новая корректировка не создаётся

#### Scenario: Роль без прав не может открыть экран создания

- **GIVEN** авторизован пользователь роли CFO или DTOE
- **WHEN** пользователь открывает `/corrections/create`
- **THEN** система отображает экран «Доступ запрещён»

### Requirement: Список типов корректировок

Система SHALL предоставлять эндпоинт `GET /org/correction-types`, доступный
любому авторизованному пользователю, возвращающий список типов корректировок
с опциональной фильтрацией по параметру запроса `isActive`.

#### Scenario: Список типов корректировок возвращается авторизованному пользователю

- **GIVEN** авторизован пользователь любой роли
- **WHEN** клиент выполняет `GET /org/correction-types`
- **THEN** сервер отвечает `200` со списком типов корректировок

#### Scenario: Фильтрация по активности

- **GIVEN** в справочнике есть активные и неактивные типы корректировок
- **WHEN** клиент выполняет `GET /org/correction-types?isActive=true`
- **THEN** сервер отвечает только активными типами корректировок

#### Scenario: Неавторизованный запрос отклоняется

- **WHEN** неавторизованный клиент выполняет `GET /org/correction-types`
- **THEN** сервер отвечает `401`
