## Why

До этого change роль FILIAL видела на `/dashboard` только заголовок «Мои
корректировки» без единого содержательного элемента: `getCorrectionStatsFilial()`
запрашивался, но результат нигде не выводился. `docs/tz/filial-cabinet.md` (ЧТЗ
v3.0 «Кабинет Филиала») описывает 10 задач роли — ни задача 1 («создать
корректировку»), ни задача 3 («направить пакет») не решаются интерфейсом, если
негде увидеть список своих корректировок и негде создать новую: маршрута
`/corrections/create` не существовало, а backend-эндпоинт `GET
/org/correction-types`, нужный форме создания, не существовал вовсе — у домена
`org` (`apps/backend/src/org/`) были только TypeORM entities, ни одного
контроллера.

## What Changes

- Экран `/dashboard` для роли FILIAL дополнен содержимым: 4 плитки статистики
  (Всего / На проверке / Возвращено / Согласовано ДТОиР, с цветовым акцентом —
  жёлтый/красный/зелёный), донат-график по 4 укрупнённым группам статуса
  (Черновик / В работе / Возвращено / Согласовано) с легендой, фильтр по группе
  синхронизированный с кликом по графику и легенде, таблица корректировок (ID,
  Тип, Статус, Этап, Создано, Изменено, кнопка «Открыть»), кнопка «+ Создать
  корректировку», пустое состояние.
- **Отклонение от ЧТЗ v3.0, раздел 0.4**: ЧТЗ предлагает выделенный маршрут
  `/filial` с `/dashboard` как чистым технический редиректом. Сохранена
  действующая архитектура `role-scoped-sections` (единый `/dashboard`,
  рендеринг по роли) — решение продукта, принято явно в ходе реализации, см.
  `design.md`.
- **Отклонение от ЧТЗ v3.0, раздел 2.2/2.4**: вместо 5 групп статуса и двух
  секций фильтра (укрупнённая группа + точный статус) в итоговой версии — 4
  группы (статусы `ALL_CFO_APPROVED`/`SENT_TO_DTOE` объединены с «В работе»,
  отдельная группа «Готово к ДТОиР» убрана) и только секция «Укрупнённая
  группа» в фильтре, без списка из 10 точных статусов — решение продукта,
  принято явно в ходе реализации.
- Новый маршрут `/corrections/create`: выбор типа корректировки (единственный
  параметр создания), кнопка «Создать» неактивна без выбранного типа, редирект
  на карточку созданной корректировки; доступен только роли FILIAL (для прочих
  ролей — экран «Доступ запрещён»).
- Новый пункт меню сайдбара «Создать корректировку» → `/corrections/create`,
  виден только роли FILIAL.
- Новый backend-эндпоинт `GET /org/correction-types` (список типов
  корректировок, фильтр `isActive`) — контракт уже был описан в
  `api/src/paths/org-correction-types.yaml` и использовался Kubb-кодогеном
  фронтенда, но не имел серверной реализации.

## Capabilities

### New Capabilities

- `filial-cabinet`: экран «Мои корректировки» роли FILIAL (плитки статистики,
  донат-график с фильтром, таблица, создание корректировки) и backend-список
  типов корректировок, поддерживающий форму создания.

### Modified Capabilities

- `private-navigation`: добавлен ролезависимый пункт меню «Создать
  корректировку», видимый только роли FILIAL — расширяет существующее
  требование «Пункты меню навигации в сайдбаре» (ранее описывало только
  универсальные для всех ролей пункты).

## Impact

- **Frontend**: `apps/frontend/app/(private)/dashboard/components/filial-dashboard.tsx`,
  `correction-stats-grid.tsx` (новый, переиспользуется CFO/DTOE-дашбордами),
  `donut-chart.tsx` (новый), `filial-corrections-overview.tsx` (новый);
  `apps/frontend/app/(private)/corrections/create/page.tsx` +
  `components/create-correction-form.tsx` (новые); `apps/frontend/app/(private)/constants.ts`
  (ролезависимые `NavItem`), `apps/frontend/src/components/sidebar-nav/sidebar-nav.tsx`
  (фильтрация пунктов по роли). Побочный рефакторинг: `status-labels.ts`
  перенесён из `app/(private)/corrections/[humanId]/lib/` в общий
  `app/(private)/lib/` — теперь используется и `/dashboard`, и `/corrections/[humanId]`.
- **Backend**: новый домен-контроллер `apps/backend/src/org/org.controller.ts` +
  `org.module.ts` + `dto/find-correction-types-query.dto.ts`, зарегистрирован в
  `apps/backend/src/app.module.ts`. Изменений схемы БД не требуется (`CorrectionType`
  entity уже существовала).
- **API-контракт**: контракт не менялся — `GET /org/correction-types` уже был
  описан в `api/src/paths/org-correction-types.yaml`/`api/src/openapi.yaml` и
  использовался фронтендом (`useGetCorrectionTypes`); этим change реализована
  только серверная часть уже существующего контракта.
- **Вне области**: полный CRUD `org`-домена (создание/изменение/удаление
  филиалов, ЦФО, типов корректировок, требований пакета, связей филиал-ЦФО) —
  контракт для него уже описан в `api/src/paths/org-*.yaml` и присутствует в
  Kubb-кодогене, но не реализован ни на один эндпоинт кроме списка типов
  корректировок; реализуется отдельным будущим change по мере необходимости
  административного интерфейса. Остальные разделы ЧТЗ v3.0 «Кабинет Филиала»
  (разделы 4, 5 — карточка корректировки и точки сопряжения с ЦФО) не входят в
  этот change: они уже были реализованы ранее и соответствуют ЧТЗ без правок
  (см. `design.md`, раздел Context).

## Влияние на качество

- **Уровень риска**: P1 — новый пользовательский маршрут (`/corrections/create`),
  новое содержимое существующего маршрута (`/dashboard` для роли FILIAL),
  новый backend-эндпоинт без изменения прав доступа к существующим данным и без
  изменения статусной модели корректировок.
- **Затронутые маршруты**: `/dashboard` (содержимое для роли FILIAL),
  `/corrections/create` (новый).
- **Затронутые frontend-компоненты**: `FilialDashboard`, `CorrectionStatsGrid`
  (общий с `CfoDashboard`/`DtoeDashboard`), `DonutChart`, `FilialCorrectionsOverview`,
  `CreateCorrectionForm`, `SidebarNav`.
- **Затронутые backend-модули**: новый `org` (`OrgController`, `OrgModule`).
- **Затронутые API**: `GET /org/correction-types` (backend-реализация уже
  существующего контракта), `GET /corrections` и `POST /corrections` (без
  изменений контракта, переиспользуются существующие эндпоинты).
- **TDD-порядок**: НЕ соблюдён — реализация велась без предварительных
  падающих тестов (итеративная разработка по ходу диалога с пользователем, не
  `/openspec-apply-change`). Тесты для нового кода на момент фиксации этого
  change отсутствуют — см. явный gap в `test-plan.md`.
- **Обязательные уровни проверки**: Static (`tsc --noEmit`, `eslint`) — выполнены,
  0 ошибок в затронутых файлах. Backend Unit/Feature, Frontend Unit/Component/E2E —
  НЕ выполнены для нового кода (см. `test-plan.md`, раздел Gaps). Существующий
  backend Jest-набор (15/15) и существующий frontend unit-набор (39/39)
  прогнаны и остаются зелёными после изменений.
- **Ручные проверки или waiver**: ручная проверка через прямые HTTP-запросы
  (curl) под демо-аккаунтом `filial.donbassgaz@demo.local` — подтверждены
  корректная форма ответа `GET /corrections`, `GET /org/correction-types`,
  SSR-рендер `/dashboard` и `/corrections/create`. Визуальная проверка в
  реальном браузере и component/E2E-тесты — waiver: в dev-контейнере
  frontend отсутствует установленный Chromium для Playwright (Vitest Browser
  Mode), а `chromium-cli` недоступен в среде агента (Windows/Git Bash) —
  инфраструктурное ограничение окружения, не связанное с этим change.
- **План отката**: изменения аддитивны (новые маршруты, новый backend-контроллер
  для уже описанного в контракте эндпоинта, новые компоненты) — откат
  равносилен revert соответствующих коммитов без обратных миграций БД.
