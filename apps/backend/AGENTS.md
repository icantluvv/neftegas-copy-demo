# apps/backend/AGENTS.md

Инструкции для AI-агентов уровня backend-контура Дэшборд Нефтегаз. Кросс-контурные
правила — в корневом `AGENTS.md`.

## Стек

Node.js, NestJS 11, TypeORM, PostgreSQL, Jest. Аутентификация — Passport + JWT
(`src/auth`). Валидация DTO — `class-validator`/`class-transformer`. API-документация
генерируется через `@nestjs/swagger`, но source of truth контракта — `api/src/openapi.yaml`
(см. корневой `AGENTS.md`, правило contract-first).

## Структура доменов

Backend организован как домены в `src/<domain>/`:

| Домен           | Каталог             | Назначение                                                        |
|-----------------|----------------------|---------------------------------------------------------------------|
| `auth`          | `src/auth/`          | Вход по email/паролю, JWT-стратегии, guard'ы аутентификации        |
| `users`         | `src/users/`         | Пользователи, роли                                                  |
| `org`           | `src/org/`           | Организационная структура: филиалы, ЦФО, типы корректировок, состав пакета документов |
| `corrections`   | `src/corrections/`   | Корректировки, слоты документов, версии файлов, замечания, история |
| `notifications` | `src/notifications/` | Уведомления пользователей                                          |
| `common`        | `src/common/`        | Общие декораторы и guard'ы                                          |
| `database`      | `src/database/`      | Подключение к БД, сидинг (`npm run seed`)                           |

## Модель данных

Схема БД реализована как TypeORM-сущности в `src/<domain>/entities/*.entity.ts` —
это единственный source of truth конкретных типов колонок и constraint'ов (аналогично
`api/src/openapi.yaml` для HTTP-контракта). Таблицы ниже фиксируют бизнес-смысл полей
и обязательность; при расхождении с кодом код в приоритете, но расхождение — повод
актуализировать эту таблицу.

Бизнес-термины (Корректировка, Замечание, Слот, Версия файла, ЦФО, ДТОиР) — см.
глоссарий в корневом `AGENTS.md`.

### User

Файл: `users/entities/user.entity.ts`.

| Поле            | Тип                       | Обязат. | Описание                                                                                                                                    |
|------------------|-----------------------------|----------|-------------------------------------------------------------------------------------------------------------------------------------------------|
| `id`             | uuid                        | да       | Первичный ключ.                                                                                                                                   |
| `email`          | string, unique              | да       | Логин. Единственный способ входа — email + пароль.                                                                                                |
| `password_hash`  | string                      | да       | bcrypt/argon2, не возвращается ни в одном API-ответе.                                                                                             |
| `role`           | enum: FILIAL / CFO / DTOE   | да       | Определяет доступный кабинет и права.                                                                                                             |
| `first_name`, `last_name` | string             | нет      | Отображаемое имя.                                                                                                                                  |
| `filial_id`      | FK → Filial, nullable       | условно  | Заполняется только при `role = FILIAL`.                                                                                                           |
| `cfo_id`         | FK → CFO, nullable          | условно  | Заполняется только при `role = CFO`.                                                                                                              |
| `is_active`      | boolean                     | да       | Деактивированный пользователь не может войти (используется вместо физического удаления — на записи пользователя есть защищённые от удаления ссылки: авторство корректировок, замечаний, версий файлов). |

### Filial / CFO / FilialCFO

| Поле                          | Тип                              | Обязат. | Описание                                                                                                                       |
|--------------------------------|-------------------------------------|----------|------------------------------------------------------------------------------------------------------------------------------------|
| `Filial.code`                  | string, unique                     | да       | Донбассгаз / Луганскгаз / Запорожгаз / Херсонгаз.                                                                                 |
| `CFO.code`                     | string, unique                     | да       | 17 значений: АНГНКС, Бухгалтерия, ОГМ, ОГС, ОГЭ, ОТЭОГС, ПОА, ПОЗК, ПОМО, ПОЭКС, ПОЭМГ, СИУС, СКЗ, СОРиСОФ, СППБ, ТРО, ХОСЭЗИС.       |
| `FilialCFO (filial_id, cfo_id)`| составной уникальный ключ          | да       | Связь M:N — какие ЦФО обслуживают какой филиал. Определяет список ЦФО, доступных филиалу при направлении, и список филиалов, доступных ЦФО в фильтре. |

### CorrectionType / PackageRequirement

| Поле                                     | Тип     | Обязат. | Описание                                                                                     |
|---------------------------------------------|-----------|----------|--------------------------------------------------------------------------------------------------|
| `CorrectionType.code`, `name`               | string    | да       | Тип корректировки (справочник, минимум одна запись — «Стандартная корректировка программы»).       |
| `PackageRequirement.correction_type_id`     | FK        | да       | К какому типу относится требование.                                                              |
| `PackageRequirement.slot_label`             | string    | да       | Название слота: «Excel корректировка», «Пакет документов», «Счета на оплату».                     |
| `PackageRequirement.is_required`            | boolean   | да       | Обязательный слот блокирует направление, пока не заполнен.                                        |
| `PackageRequirement.sort_order`             | int       | да       | Порядок отображения в карточке.                                                                   |

### Correction (Корректировка)

Файл: `corrections/entities/correction.entity.ts`.

| Поле                    | Тип                        | Обязат.                             | Описание                                                                    |
|--------------------------|-------------------------------|---------------------------------------|----------------------------------------------------------------------------------|
| `id` / `human_id`        | uuid / string                 | да                                     | `human_id` формата `COR-000001`, генерируется автоинкрементом, отображается пользователю. |
| `filial_id`               | FK → Filial                   | да                                     | Филиал-автор.                                                                     |
| `correction_type_id`      | FK → CorrectionType            | да                                     | Определяет состав слотов при создании.                                            |
| `author_id`               | FK → User                      | да                                     | Кто создал (пользователь роли FILIAL).                                            |
| `status`                  | enum (10 значений, см. раздел «Статусы корректировки») | да | Текущий статус жизненного цикла.                                                  |
| `created_at` / `decided_at` | timestamp                    | `created_at` — да, `decided_at` — нет | `decided_at` заполняется только при переходе в `APPROVED_BY_DTOE`.                |

### DocumentSlot / FileVersion

| Поле                                          | Тип                          | Обязат. | Описание                                                                                              |
|-------------------------------------------------|---------------------------------|----------|-------------------------------------------------------------------------------------------------------------|
| `DocumentSlot.correction_id`, `requirement_id`   | FK                              | да       | Один слот на каждый `PackageRequirement` типа корректировки, создаются при создании корректировки.            |
| `FileVersion.slot_id`                            | FK                              | да       | К какому слоту относится.                                                                                     |
| `FileVersion.version_number`                     | int, автоинкремент в рамках слота | да    | 1, 2, 3… Версии не удаляются и не перезаписываются.                                                            |
| `FileVersion.file`                                | file path / storage key         | да       | Физическое хранение файла (объектное хранилище или диск сервера).                                              |
| `FileVersion.uploaded_by_id`, `uploaded_at`       | FK, timestamp                   | да       | Кто и когда загрузил.                                                                                          |
| `FileVersion.remark_id`                           | FK → Remark, nullable           | нет      | Заполняется, если версия загружена в ответ на конкретное замечание — связывает исправление с претензией.       |

### CorrectionCFOStatus

| Поле                          | Тип                                          | Обязат. | Описание                                                                       |
|---------------------------------|--------------------------------------------------|----------|-------------------------------------------------------------------------------------|
| `correction_id`, `cfo_id`       | FK, уникальная пара                              | да       | Независимый статус согласования каждого направленного ЦФО по корректировке.          |
| `status`                        | enum: PENDING / APPROVED / RETURNED               | да       | PENDING — ждёт решения, APPROVED — согласовал, RETURNED — вернул с замечанием.        |
| `decided_at`, `decided_by_id`   | timestamp, FK                                     | нет      | Когда и кем принято решение.                                                        |

### Remark (Замечание)

Файл: `corrections/entities/remark.entity.ts`.

| Поле                        | Тип                          | Обязат.               | Описание                                                                                                                    |
|-------------------------------|---------------------------------|--------------------------|------------------------------------------------------------------------------------------------------------------------------------|
| `id` / `human_id`             | uuid / string `REM-000001`      | да                        | Человекочитаемый ID.                                                                                                                |
| `correction_id`                | FK                              | да                        | К какой корректировке относится.                                                                                                    |
| `slot_id` (`related_slot`)     | FK → DocumentSlot                | да                        | Обязательная привязка к конкретному элементу пакета — фиксируется автоматически при открытии формы через кнопку «Оставить замечание к элементу», пользователь не выбирает элемент вручную. |
| `cfo_id`                       | FK → CFO, nullable               | нет                       | NULL означает, что замечание от ДТОиР.                                                                                              |
| `author_id`                    | FK → User                        | да                        | Конкретный пользователь, оставивший замечание.                                                                                      |
| `description`, `required_action` | text                            | `description` — да        | Что не так и что нужно сделать.                                                                                                     |
| `sheet_name`, `row_ref`        | string                           | нет                       | Опциональная точная привязка внутри Excel-файла (лист, строка).                                                                     |
| `status`                       | enum: OPEN / FIXED_BY_FILIAL / CLOSED | да                  | OPEN — открыто, FIXED_BY_FILIAL — филиал отметил исправленным, CLOSED — проверяющий подтвердил при повторном согласовании.          |
| `created_at`, `closed_at`      | timestamp                        | `created_at` — да          | —                                                                                                                                    |

### CorrectionHistoryEntry / Notification

| Поле                                                                  | Обязат. | Описание                                                                                                          |
|--------------------------------------------------------------------------|----------|------------------------------------------------------------------------------------------------------------------------|
| `CorrectionHistoryEntry (correction_id, user_id, timestamp, text)`       | да       | Неизменяемый лог. Пишется системой при каждом значимом событии, недоступен для редактирования и удаления даже автору.  |
| `Notification (user_id, correction_id, is_read, created_at, text)`      | да       | Внутрисистемное уведомление. `is_read` переключается при открытии соответствующей корректировки из списка уведомлений. |
